# EduAgent Architecture

## 1. Runtime shape

EduAgent is deliberately a single-process Streamlit application. `app.py` loads configuration, constructs a cached `AppServices` container, renders shared navigation, and dispatches to focused page functions in `src/eduagent/ui/pages.py`.

```text
app.py
  ├── Settings
  ├── StudentRepository (SQLite)
  ├── ChromaVectorStore
  ├── OpenAICompatibleProvider
  ├── IngestionService
  ├── Retriever
  ├── TutorAgent
  └── Streamlit page renderers
```

There is no external database server, background queue, authentication service, or separate frontend in the MVP.

## 2. Document ingestion

`parse_pdf` uses PyMuPDF to extract text page by page. It normalizes whitespace and stores page metadata. `chunk_pages` splits each page independently so every chunk keeps an unambiguous citation. `IngestionService` hashes raw file bytes, skips duplicate content, embeds chunks, writes them to Chroma, and registers a document manifest in SQLite.

## 3. Retrieval

The production vector layer is Chroma with a local persistent client and cosine distance. Each vector record stores its chunk text and `document_name`, `document_hash`, `page`, and `chunk_id` metadata.

`Retriever` embeds a question, requests top-k results, converts them to `RetrievedChunk`, and formats a grounded prompt context. Source cards are generated by the application from retrieved metadata; the LLM does not invent citation strings.

## 4. Provider abstraction

`OpenAICompatibleProvider` wraps chat completions and embeddings. It accepts `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_MODEL`, and `OPENAI_EMBEDDING_MODEL`. The provider supports plain text and Pydantic-validated JSON. If JSON validation fails, it makes one bounded repair request. It does not log prompts, retrieved excerpts, or student answers.

Tests use fake providers and fake retrievers. The app does not silently display fake answers when credentials are missing.

## 5. Tutor Agent

`TutorAgent` exposes:

```text
answer_question(question, level, profile)
generate_quiz(topic, question_type, difficulty, profile)
evaluate_answer(quiz, submitted_answer, profile)
```

The LLM generates content. The application controls policy. This boundary is important: model prose can be probabilistic, but the MVP's next-action selection is deterministic and testable.

## 6. Teaching policy

```text
no prior attempt       → EXPLAIN
mastery < 0.40         → REVIEW_PREREQUISITE
latest score < 0.50    → GIVE_EXAMPLE
mastery < 0.75         → GENERATE_QUIZ
otherwise              → INCREASE_DIFFICULTY
```

The policy returns a short reason for observability. It does not expose hidden chain-of-thought.

## 7. Student model

For a score `s` in `[0, 1]`:

```text
first attempt:  mastery = s
later attempts: mastery = 0.70 × previous_mastery + 0.30 × s
average_score: arithmetic mean of all attempts
weak concept:  mastery < 0.60
```

SQLite stores profiles, concept states, quiz attempts, interactions, and document manifests. The model is intentionally interpretable and must not be described as scientifically validated knowledge tracing.

## 8. UI and state

- **Learn:** chat messages in Streamlit session state; successful Q&A interactions also persist in SQLite.
- **Course Materials:** multi-file uploader and explicit indexing action.
- **Practice:** active quiz and evaluation in session state; quiz attempt is written once to SQLite.
- **Progress:** overview metrics, mastery table, weak concepts, and recent attempts.
- **About:** product purpose and limitations.

SQLite is the source of truth for learner history. Session state holds transient UI state such as the active quiz and chat display.

## 9. Evaluation

The technical evaluator accepts a JSON dataset with expected source document and page. It reports retrieval hit rate, source recall, latency, optional answer-generation success, and provider errors.

The included CLI uses self-authored content and a small lexical retriever to remain runnable without credentials. It is a smoke evaluation, not a scientific benchmark. A future experiment is described separately in `docs/impact_study.md`.

## 10. Deployment and privacy

Streamlit Community Cloud can run the single-process app from `app.py` with secrets configured in the dashboard. The hosted filesystem may be ephemeral, so persistent multi-user production use would require a reviewed storage design. API keys stay in secrets; uploaded documents and runtime databases are ignored by Git and should not be treated as automatically private in a hosted environment.
